# 月笺 Lunote 协议说明

> 版本：协议 v1（发现 LUNOTE1 / 会话帧 / 传输 / 记录导出）。
> 所有协议均为本产品独立设计，不复制任何第三方协议。

## 1. 发现协议（UDP，明文信标）

- 端口：`45454/UDP`（可配置）
- 发送：IPv4 组播 `239.255.77.77`（TTL=1，逐接口）+ 有限广播 `255.255.255.255`
  + 各接口子网定向广播
- 报文（一行 UTF-8，名称百分号编码）：

```
LUNOTE1|ver=1|name=<编码名>|dev=<设备ID>|inst=<实例ID>|seq=<序号>|ts=<毫秒>|port=<TCP端口>
```

字段：

| 字段 | 含义 |
| --- | --- |
| ver | 协议版本（必须为 1；未知版本忽略并记日志，不误判为设备） |
| name | 设备显示名（百分号编码，最长 256 字符） |
| dev | 持久设备 ID（UUID，重启不变） |
| inst | 实例 ID（每次启动随机；用于区分重启与同名设备） |
| seq | 单调序号（去重重复包） |
| ts | 发送毫秒时间戳 |
| port | 本机 TCP 会话端口（45455，可配置） |

接收端规则：

- 畸形包 / 未知版本 / 缺字段 → 忽略并计数（rx_invalid）；
- seq ≤ 已见 → 重复包（rx_dup）；
- 同 device_id 新 instance_id → 设备重启，替换旧实例（信任关系保留）；
- 同名设备按 dev 区分，不合并；
- 同一实例名称变化 → 更新显示名（身份不变）；
- 超过 timeout 未收到信标 → 离线事件；超时 4 倍仍无 → 移除记录；
- 多网卡：逐接口组播发送；同一设备经多接口出现时以最新实例为准；
- 后台节流：无传输时信标间隔 ×3，保留接收能力。

## 2. 会话协议（TCP + TLS 1.3）

- 端口：`45455/TCP`（可配置，发现信标中广播）
- 握手顺序（TLS 通道内）：

```
服务端 ──32字节随机challenge──▶ 客户端
客户端 ──Hello(JSON)─────────▶ 服务端   （含自身challenge+证书+签名）
服务端 ──HelloAck(JSON)──────▶ 客户端   （签名自身身份）
```

- `Hello` / `HelloAck` 字段：device_id、name、instance_id、challenge(base64)、
  cert_b64、sig_b64、ts_ms；签名对象 = `challenge‖device_id‖name‖instance_id`
  （challenge 为对端发出的随机数，每次连接新鲜，防重放）。
- 身份判定：证书指纹（SHA-256(证书 DER)）与 TOFU/信任库比对，
  结果 New / Same / Changed（Changed → 警告 + 降级）。
- 帧格式：`[4B 载荷长度 LE][1B kind][载荷]`；kind=0 JSON 控制，kind=1 二进制分块。

## 3. 控制消息（JSON，kind=0）

| type | 方向 | 说明 |
| --- | --- | --- |
| text | 双向 | 消息 id、文本、时间戳 |
| link | 双向 | 消息 id、url、可选标题 |
| file_offer | 发送→接收 | transfer_id、净化名、大小、可选 sha256、可选相对路径、resume_token |
| file_accept | 接收→发送 | transfer_id、offset（续传起点）、partial_sha256（已收部分哈希） |
| file_reject | 接收→发送 | transfer_id、原因 |
| file_restart | 发送→接收 | 部分校验不一致，要求清空临时文件从头开始 |
| chunk_ack | 接收→发送 | transfer_id、seq、offset（每 16 块或收满时） |
| file_done | 发送→接收 | transfer_id、sha256、size；接收端校验后回执同帧 |
| file_cancel | 双向 | transfer_id、原因 |
| ping / pong | 双向 | 心跳 |
| bye | 双向 | 优雅关闭 |

## 4. 文件传输

- 分块：256 KiB；窗口 16 块（4 MiB）未确认上限；ACK 每 16 块或收满。
- 完整性：双端增量 SHA-256，`file_done` 比对；失败删除临时文件。
- 断点续传：接收端保留 `.part` 与 `.lunote-resume/<token>.json` 元数据；
  重连后新 offer 携带同一 resume_token → 接收端回
  `file_accept{offset, partial_sha256}` → 发送端校验部分哈希后 seek 接续；
  不一致 → `file_restart`。
- 取消：任一侧 `file_cancel`；接收端删除 `.part`。
- 连接断开：接收端保留 `.part`（可续传），状态标记 Failed(可续传)。
- 文件夹：逐文件发送，`rel_path` 携带相对路径；接收端净化后重建目录。
- 目标文件名冲突：自动追加 ` (1)`、` (2)`。

## 5. 本地记录与导出格式

- 存储：SQLite 三表（conversations / messages / transfers），
  消息内容逐条 AES-256-GCM（随机 nonce），密钥 `records.key`。
- 导出文件：

```
[9B 魔数 "LUNOTEXP1"][4B 版本=1][16B salt][12B nonce1][48B 包裹DEK]
[12B nonce2][AES-256-GCM(DEK, JSON)]
```

- KEK = Argon2id(密码, salt, 64MiB, t=3, p=1)；DEK 随机 32 字节，
  AES-256-GCM(KEK) 包裹；载荷 JSON 含导出时间与完整会话（消息+传输记录）。
- 导入：校验两层 GCM 标签；按消息 UUID `INSERT OR IGNORE` 去重。
