# 局域网传输应用开发路径指南

> 本文是“从零开发一个局域网直连传输应用（发现→信任→TLS→消息/文件）”的路径指南，
> 以月笺 Lunote 的真实开发经历为底稿：每个阶段做什么、怎么做、真实踩过的坑、如何真实验证。
> 环境参考：Windows 开发机 + 雷电桥接 Android 模拟器（192.168.3.10），PC 192.168.3.9，
> 时间戳一律 UTC（本地 = UTC+8）。

## 路径总览

```
0. 架构决策 → 1. 设备发现 → 2. 身份与信任 → 3. 安全会话 → 4. 消息/文件传输
→ 5. 本地加密记录 → 6. UI 数据链路（最大坑区）→ 7. 日志与诊断 → 8. 构建/测试/发布
```

每阶段三件事：**做什么 → 坑在哪 → 怎么验证**。验证永远是真实验证（真实 socket、真实进程、真实 App），不做静态演示。

---

## 阶段 0：架构决策

| 决策点 | 建议 | 理由 |
| --- | --- | --- |
| 核心与 UI 分层 | Rust 核心（协议/状态机）+ UI 壳（Flutter/其他） | 核心可无头运行（CLI），UI 只是消费者；出问题先分层定位 |
| 核心 API 形态 | JSON 命令 + 事件流（FFI 桥 / 控制文件） | 调试友好，CLI/UI/测试共用一套语言 |
| 无云端无账号 | 局域网直连，TOFU 信任 | 产品定位；也大幅简化部署 |
| 传输加密 | TLS 1.3（rustls）自签证书 + 应用层签名挑战 | 防中间人/防重放；证书即设备身份 |

## 阶段 1：设备发现（互相发现的全部真相）

### 做什么
- UDP 信标协议（如 `LUNOTE1|ver=1|name=..|dev=..|inst=..|seq=..|ts=..|port=..`）
- 发送：**组播（239.255.77.77:45454，TTL=1）+ 有限广播 + 各网卡子网定向广播** 三路齐发，逐网卡绑定
- 接收：去重（seq）、自己回环过滤、离线超时、重启替换（instance_id）、改名更新
- 频率：信标 1 秒一发，离线判定 4 秒；退后台节流（×3）

### 坑在哪
1. **Android 收不到组播** → Wi-Fi 节能过滤组播，必须 `WifiManager.MulticastLock` + `CHANGE_WIFI_MULTICAST_STATE` 权限。
2. **标准 Android 模拟器（NAT）组播/广播根本穿透不了** → 用桥接模式模拟器（与 PC 同网段），行为等同真机。
3. **“互不发现”一半是假象**，按顺序排查：
   - 两端是否同时在线（发现是实时握手）；
   - 是否有一端是旧版本（信标字段/日志特征不同）；
   - 日志时间戳是否 UTC（16:29Z = 次日 00:29 本地，容易误判“旧日志”）；
   - 核心日志是否正常（正常但 UI 空 → 跳阶段 6，别在发现层浪费时间）；
   - 是否退后台节流导致被对端判离线（设计行为）。
4. **统计行误导**：诊断统计 30 秒打一行曾让人误以为“发现间隔 30 秒”——信标一直是 1 秒。统计打印改为 10 秒。
5. **回环与重复包**：`rx_self`（自己回环）、`rx_dup`（组播+广播多份拷贝）高是正常的，别当 bug 修。

### 怎么验证
- 核心每 10 秒打一行统计：`发现统计 tx=.. rx_total=.. rx_valid=.. rx_self=.. rx_dup=.. rx_invalid=.. peers=[名@IP:端口]`
  - `rx_total=0` → 网络根本没通（组播被过滤 / NAT / 防火墙）
  - `rx_invalid` 非 0 → 对端协议版本不符
  - `peers=[...]` 列出已知设备 → 核心层发现结论的唯一依据
- 本机双 CLI 实例（不同 TCP 端口、共享 UDP 组播）即可验证发现→离线→重启替换全流程。

## 阶段 2：身份与信任

### 做什么
- Ed25519 密钥 + 自签名证书（rcgen），指纹 = SHA-256(证书)，持久落盘
- TOFU：首次见 → 用户按钮确认 + 指纹短码展示；身份变化 → 警告并降级
- 未信任设备可发文字/链接，文件必须信任 + 逐次确认

### 坑在哪
- 密钥/证书文件权限（Windows 依赖目录 ACL）；平台密钥库（DPAPI/Keystore）包裹列为后续改进，先如实标注边界。
- 指纹核对依赖 UI 展示——UI 数据链路断（阶段 6）时指纹也看不到，会连锁产生“信任不了”的假象。

### 怎么验证
- 单元测试：证书生成、指纹稳定、身份变化检测。
- e2e：本机双实例真实 socket 完成 TOFU → 信任 → 拒绝未信任文件。

## 阶段 3：安全会话（TLS 1.3）

### 做什么
- rustls(ring) 仅 TLS 1.3；自签证书双向认证；应用层签名挑战（challenge‖device_id‖name‖instance_id）防重放
- 连接管理：读/写独立任务（**禁止 select 取消半途 IO**，会损坏流）、心跳 15s、空闲 60s 关闭、watch-channel 关停信号

### 坑在哪
- 早期用 `tokio::select!` 同时做读写取消 → 流损坏。读/写必须各归各的任务，取消只走关闭通道。
- 会话建立前的 device 地址要查发现层快照；地址变了要重新解析。

### 怎么验证
- e2e：TLS 握手 → 文字往返 → 断线重连 → 重启替换。

---

## 阶段 4：消息/文件传输

### 做什么
- 消息：文字、链接（自动识别 URL）
- 文件/文件夹：256KiB 分块、16 块滑动窗口、双端增量 SHA-256、`.part` + 原子改名、路径净化防穿越、断点续传（resume_token + 部分哈希校验）

### 坑在哪
- 路径净化：相对路径组件逐段校验，防 `../` 穿越。
- 续传一致性：部分哈希不一致必须从头重传，别“自信续传”。
- 传输记录不存文件哈希（隐私权衡）——完整性只在传输时校验，文档写明边界。

### 怎么验证
- e2e：文件+文件夹 SHA-256 完整性、取消、断点续传、未信任拒绝。
- 跨进程回归：两个独立 CLI 进程真实传文件并比对哈希。

## 阶段 5：本地加密记录与导出

### 做什么
- SQLite + 逐记录 AES-256-GCM（随机 nonce），密钥独立文件
- 导出 = 独立密码（Argon2id）+ AES-256-GCM 信封；导入按 UUID 去重；错误密码/篡改拒绝

### 坑在哪
- 导出文件自包含加密容器，密码丢失 = 不可恢复（写进安全模型文档）。
- 元数据（会话名/时间戳）不加密、内容加密——如实声明边界。

### 怎么验证
- 单元 + e2e：数据文件无明文断言、错误密码拒绝、篡改拒绝、跨实例导出导入。

## 阶段 6：UI 数据链路（“为什么不显示”的最大坑区）

> 这一阶段单独成章：**核心日志一切正常，但 UI 设备列表空、按钮无反应、导出无内容**。
> 核心（Rust）与 UI（Dart）之间有独立的数据链路，**核心正常 ≠ UI 正常**。

### 6.1 头号元凶：FFI worker isolate 没初始化它自己的依赖

- **现象**：设备页永久空白、一键导出无弹窗、无法信任/发消息；核心日志一切正常。
- **根因**：UI 把 FFI 调用放进 `Isolate.spawn` 的 worker（避免阻塞渲染），但 **spawn 出的新 isolate 拥有全新静态区**——主 isolate 里加载过的原生库单例（`CoreNative.instance`）在 worker 里是**未加载的空壳**：
  - 事件轮询（poll）失败 → 核心事件一个都到不了 UI；
  - 命令（call）失败 → 所有 UI 操作静默失败；
  - Rust 核心跑在自己的线程上，日志照常写 → 完美假象。
- **修复**：worker 入口第一行重新 `load()` 原生库（load 做幂等：已加载直接返回）。
- **验证**：集成测试真实启动 App，断言设备页在数秒内出现在线设备。
- **通用教训**：**跨 isolate 不共享任何 Dart 状态**；凡 worker 用到的单例都要在 worker 里重新初始化。排查“核心正常但 UI 空”，先验证事件流是否真的到达 UI。

### 6.2 事件时序：启动瞬间的事件全部丢失

- **根因**：核心启动 1 秒内就发现设备并发 `peer_online`，Dart 的事件订阅在 `core.start()` 之后——广播流不缓存，订阅前的事件直接丢弃；且核心只在“新实例首次出现/离线恢复”时才再发事件 → **错过一次，永久空白**。
- **修复**（三层保险）：
  1. 订阅后**主动拉一次 peers 快照**补历史；
  2. **定时轮询快照**兜底（内容无变化不 notify，避免无谓重建）；
  3. 页面加**手动刷新按钮 + 下拉刷新**。
- **通用教训**：事件流适合做增量更新，**完整状态必须靠主动拉取**，两者结合。

### 6.3 两套数据源字段不一致

- 核心事件里端口字段是 `port`，快照命令里是 `tcp_port`；Dart 模型统一读 `tcp_port` 时事件路径端口解析成 0（当前不影响显示）。**事件与快照必须共用同一套序列化字段**。

### 6.4 图标空白：TreeShakeIcons 子集化 + 增量构建不刷新 assets

- 发布构建默认把 MaterialIcons 子集化到 4–5KB（正常机制，APK 同样如此）；但旧 assets 是旧代码的子集化结果，**不含后来新增的图标字形**，且增量构建没随 app.so 更新 assets。
- 修复：删除 `Release\data\flutter_assets` 及中间 assets，强制完整重建；**改图标/资源后核对 assets 时间戳**。

### 6.5 平台适配坑（简表）

| 坑 | 根因 | 修复 |
| --- | --- | --- |
| PC 标题栏按钮全部无效 | `ensureInitialized()` 在窗口创建前调用（native 句柄 NULL）；按钮与拖拽手势竞争 | 窗口就绪后再调一次；`DragToMoveArea` + 官方 `WindowCaptionButton` 分离 |
| 关闭按钮“没反应” | 旧实现是隐藏到托盘 | 关闭 = destroy + exit(0)，去掉 setPreventClose |
| 托盘右键不弹菜单 | tray_manager 0.2.4 Windows 只发事件不自动弹菜单 | `onTrayIconRightMouseDown` → 手动 `popUpContextMenu()` |
| APK 白屏 | window_manager 无 Android 实现，ensureInitialized 抛异常 | 桌面平台才初始化 |
| 一键导出“旧日志” | tracing 写入有缓冲；导出无预览无法核对 | 每次写后 flush；导出前弹预览（文件时间/大小/行数/末尾），复制后提示文件时间 |
| Android 插件构建失败（jni/objective_c、带空格路径） | file_picker/path_provider 特定版本问题 | 换 file_selector；钉住 path_provider 版本 |

### 6.6 UI 层验证方法

- 集成测试（真实 App + 真实网络）：注入独立数据目录/端口（避免与运行中实例冲突），断言“核心就绪 → peers 非空 → 设备页渲染出设备 IP”。
- 任何“我改了 UI”都必须跑一次集成测试或真实冒烟，**不跑不交付**。

## 阶段 7：日志与诊断体系

- **分层**：核心日志（core.log：发现统计/会话/传输）+ UI 日志（lunote_ui.log：窗口操作/导出埋点）。
- **立即落盘**：tracing 写入必须 flush，否则文件里看不到最新也会误导排查。
- **时间戳写 UTC**，向用户解释时换算本地。
- **一键诊断**：核心 10 秒统计行 + UI“一键导出诊断日志（带预览）”是远程排查的生命线。

## 阶段 8：构建/测试/发布（坑简表）

| 坑 | 根因 | 修复 |
| --- | --- | --- |
| 构建时无法覆盖 exe/dll | Windows 运行中的进程锁定文件 | 先停旧实例；脚本末尾强制再同步一次 dll |
| CLI 控制文件外部写不进 | Rust `File::open` Windows 默认只共享读 | 显式 `share_mode(FILE_SHARE_READ\|WRITE\|DELETE)` |
| 子进程输出捕获不到 | 沙箱/管道限制 | 重定向到文件（`*> log`）再读文件 |
| `Start-Process -ArgumentList` 拆碎带空格路径 | 参数拼接不引号 | 用带内嵌引号的单字符串参数 |
| Gradle 下载超时/AGP 缺失 | C/D 盘缓存不一致 | 合并 gradle 缓存，固定 `GRADLE_USER_HOME` |
| Kotlin 增量编译跨盘失败 | pub 缓存与工程跨盘 | `kotlin.incremental=false` |
| 集成测试端口冲突 | 测试实例也绑 45455 | 暴露 `tcpPortOverride` 注入 |
| Android 组播锁/权限 | 见阶段 1 | MulticastLock + 权限 |

## 一句话总结

- **发现不到**：先查“同时在线 / 网络模式（NAT?）/ 组播锁 / 防火墙”，再看 `发现统计` 行，最后才怀疑代码。
- **UI 不显示**：先问“核心日志正常吗？”——正常就 100% 是 UI 数据链路问题；头号原因是 **worker isolate 没初始化自己的依赖**，其次是 **订阅晚于事件产生**。
- **验证**：每个阶段都有对应的真实运行验证（双实例 CLI / e2e / 集成测试 / 用户日志），没有真实运行就没有“完成”。
