## 已知限制（实现层面）

- 同一会话同一时刻一个发送方向任务（多文件排队），双向互不阻塞。
- 密钥文件未做平台安全存储包裹（DPAPI/Keystore 为后续改进）。
- 发现信标明文（不含内容，含设备名）。
- 记录库元数据（会话名、时间戳）不加密，内容加密。
- 传输记录不保存文件哈希（隐私权衡），完整性在传输时校验。
- 设备页由事件流 + 3 秒快照轮询双通道驱动；启动时错过的事件由主动拉取补齐
  （2026-08-17 修复，见交付报告 2.5 节）。

## 最新状态（2026-08-18）

### 2026-08-18 剪贴板、文字拖放与传输反馈

- 对话输入栏新增系统剪贴板按钮：前台读取 Android/Windows 当前系统剪贴板文字，先预览，再选择“填入输入框”或“直接发送”。雷电模拟器已用 Android 原生 Copy 实测，完整链接可预览、填入并发送。
- Android 只能读取当前系统剪贴板，不能枚举百度输入法等输入法应用内部保存的历史剪贴板；该限制来自 Android 应用隔离，不需要额外伪造权限。
- Windows `desktop_drop` 本地插件补齐 `CF_UNICODETEXT`：拖入选中文字或链接会填入并聚焦输入框，文件拖放行为保持不变；Windows release 原生插件已重新编译通过。
- 传输核心改为每 1 MiB（或 4 块）确认一次进度，计算实际字节速率并用 70/30 指数平滑；传输卡片显示“传输速度 / 预计剩余”，进度条使用 320ms 插值动画并尊重系统减少动画设置。
- 安全回归确认：消息正文和 URL 使用逐条 AES-256-GCM 加密，`no_plaintext_in_db` 测试确认 SQLite 中不存在明文；当前 `records.key` 仍与数据库同目录，尚未由 Windows DPAPI / Android Keystore 包裹，不能宣称可抵抗取得整个应用数据目录的攻击者。
- 最终发布构建通过：Windows release、Android arm64-v8a / armeabi-v7a / x86_64 原生库和 62.6 MB APK 均已生成到 `dist`。
- 雷电模拟器覆盖安装与冷启动通过：未出现 `Bad state`、句柄 `-1`、核心启动失败或 AndroidRuntime 崩溃；与 PC 自动发现、在线和可信状态正常。
- 验证结果：`flutter analyze` 0 问题；Flutter 5/5；Rust core 22/22、bridge 4/4、e2e 7/7。Android→Windows 真实发送能进入“等待对方确认”并在超时后正确进入“失败（可续传）”；本轮外部自动化未稳定命中 Windows GPU 窗口的“接收”按钮，因此没有把实时速度截图误报为实机通过。

### 2026-08-28 Android 分享与公共目录兼容

- AndroidManifest 注册 `ACTION_SEND` / `ACTION_SEND_MULTIPLE`，月笺现在会出现在系统分享面板中；文本分享、文件分享均由原生入口接收，分享文件会复制到应用缓存后交给 Flutter 选择在线设备发送。
- 分享入口支持冷启动和应用已在前台两种情况；应用恢复时会再次拉取待处理分享内容。
- Android 发送文件夹改用 SAF `ACTION_OPEN_DOCUMENT_TREE`，选择 Download 等公共目录后递归复制到临时目录，再交给核心传输，绕开 DocumentsUI 禁止直接“使用 Download 根目录”的限制。
- 目前“接收目录”仍使用核心可直接写入的本地路径；Android 11+ 对公共 Download 根目录的 SAF 写入限制仍存在，未将 URI 伪装成本地路径。后续若要把接收结果直接落到 Download，需要增加 MediaStore/SAF 输出层。
- `flutter analyze --no-pub` 通过；Release APK 构建通过。雷电模拟器系统分享面板已实测出现“月笺 Lunote”。
