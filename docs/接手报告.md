## 0. 三句最重要的提醒（接手前先看）

1. **核心与 UI 分离**。核心(Rust)与 UI(Flutter)完全分离，通过 **FFI 桥（JSON 命令 + 事件流）** 通信。**核心日志正常 ≠ UI 正常**——UI 有独立数据链路，历史上最大 bug 就是这条链断了（详见 §9.1）。
2. **改 UI 只动 `app/lib/src/ui/**`**；核心(Bridge 以外的 crates)和 `app/lib/src/core/**`、`app_state.dart` 方法签名不要动，否则所有端一起失灵且难排查。
3. **所有实现必须有真实验证**（真实 socket / 真实进程 / 集成测试），不做静态演示；构建/测试全部后台执行、日志写文件。

## 2. 技术栈与架构

```
Flutter UI (app/) ──FFI──> lunote_bridge.dll/.so ──> lunote-core (Rust)
                             · JSON 命令 + 事件流
   cli 也走同一套命令（控制文件），可无头运行做自动化/回归
```

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 核心 | Rust：tokio + rustls(ring, 仅 TLS1.3) + Ed25519 + AES-256-GCM + rusqlite + Argon2id | crates/lunote-core |
| 桥 | C ABI：`lunote_create/call/poll/destroy/free_string` | crates/lunote-bridge |
| UI | Flutter 3.47（Android/Windows/Linux 一套）| app/ |
| 无头 | lunote-cli serve + 控制文件 | crates/lunote-cli |

### 关键设计决策
- 核心可脱离 UI 运行（CLI），UI 只是"命令 + 事件"的消费者；
- 事件广播 + 主动拉快照双通道（事件启动期会丢，所以有 3 秒轮询兜底）；
- FFI 放 worker isolate 跑（不阻塞渲染）；
- 双色板主题 = ThemeExtension `LunoteColors`（深/浅两套），页面用 `LunoteColors.of(context)` 取色。

## 4. 运行时架构（排查用）

```
main() → AppState.init:
  core.start(worker isolate: FFI load + 命令/poll轮询150ms)
  → 订阅事件流 → 主动拉 peers/trusted/conversations/settings
  → 3 秒轮询 peers（兜底事件丢失）
```

- 数据目录 = `getApplicationSupportDirectory()/data`（PC：`%APPDATA%\com.lunote\lunote_app\data`；Android 私有目录内）
  - `identity.key` + `identity.json`（身份）、`trust.json`、`records.db`（+wal/shm）、`settings.json`、`core.log`、`downloads/`
- 设置持久化：`settings.json` = `{"auto_trust":bool,"downloads_dir":str|null,"theme":"dark|light|system"}`
- 核心日志 `core.log`：**UTC 时间戳**（本地=+8）、每 10s 一行发现统计、`lunote_create 启动失败` 也写这里
- UI 日志 `%TEMP%\lunote_ui.log`

### 6.3 代码审计遗留（中危，来自交付报告 2.6 审计；低危已修大部分）
- `session.rs` 代际失效检查为死代码（`my_gen`/`generation` 同一 Arc 恒等）；被替换连接靠 close_tx 兜底，可在退出前多处理一帧。
- `connect_to` 握手完成 → spawn run_connection 即返回；会话注册在异步任务稍后执行，**建连后立刻发消息有竞态**（建议注册完成后再返回，或 push_frame 加短重试）。

## 8. 排查方法论（已经过验证有效的路径）

1. **核心层**：看 `data/core.log`（发现统计/会话/传输/启动错误）。
2. **UI 层**：看 `%TEMP%\lunote_ui.log`（窗口操作/导出埋点）。
3. **“核心正常但 UI 空”** → 90% 是 UI↔核心链路问题，查：
   - worker isolate 里 `CoreNative.instance.load()` 是否执行（**新 isolate 静态区是全新的，必须重新 load**——历史最大 bug）；
   - 事件订阅是否晚于事件产生（broadcast 不缓存）→ 靠主动拉快照 + 轮询兜底。
4. **信任/发送被拦** → 先确认 trust 记录真在（设备页信任后按钮变“可信”），再查核心 `is_trusted`。
5. **一键导出诊断日志**是远程排查的主通道（带预览确认最新）。
